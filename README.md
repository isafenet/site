# isafenet.app

The iSafeNet company website: https://isafenet.app (GitHub Pages, custom domain in `CNAME`).

```
python3 tools/make_assets.py              # images: logo mark, favicons, social card and every app's screens
python3 tools/make_assets.py --apps-only  # just the app icons and screens (no brand pack needed)
python3 tools/build.py                    # every page, sitemap.xml, robots.txt, 404.html and the board's app list
```

**Never edit the generated HTML by hand**: `build.py` rewrites every page. Page content lives in `tools/build.py`
(company pages) and `apps/<key>.json` (one file per app). Both scripts are deterministic.

`make_assets.py` reads the iSafeNet brand pack (default `~/Downloads/iSafeNet_Digital_Assets_Pack`, or `--pack`)
and each app's website checked out beside this repo (e.g. `../udapt-web`; the folder is `images_from` in the
app's file). Re-run it when an app's screenshots change.

The company site and each app's site link to each other: every app page here deep-links into its app's site, each
app site links back to iSafeNet, and all of them name `https://isafenet.app/#organization` as the publisher in their
structured data.

## Adding an app

Everything that lists the apps (nav, footer, homepage card, "More from iSafeNet", structured data, sitemap,
404 page, privacy page, the social card and the feedback board) is built from `apps/*.json`.

1. `python3 tools/build.py --new-app <key>`: `<key>` is the short lower-case name (`udapt`). It becomes the page
   (`udapt.html`), the image prefix (`udapt-…`) and the feedback board's app ID. This writes `apps/<key>.json`.
2. Fill in every `TODO` in that file. `apps/udapt.json` is a complete example. Notes:
   - Paths in `footer`, `links` and `second_button` are relative to the app's own website unless they're full URLs.
   - `screens` gives alt text for every screenshot the page uses; `framed_screens` lists the ones that already show
     a device frame (marketing panels), so the site doesn't draw another.
   - `images_from` says where `make_assets.py` copies the icon and screenshots from.
   - `order` sets its place in the nav and on the homepage; `colors` are the card's background gradient.
3. `python3 tools/make_assets.py --apps-only <key>` to copy its images, then `python3 tools/build.py`.
   The build stops with a list of anything missing (a TODO left, a screenshot without alt text, an image not copied).
4. Check it locally (`python3 -m http.server 8000`, then http://localhost:8000), then commit and push.
5. Redeploy the feedback board's API so it accepts ideas for the new app: `cd feedback-api && npm run deploy`.
   No database change is needed.
6. When there's a brand pack to hand, run the full `python3 tools/make_assets.py` to refresh the social card, which
   names every app.

To remove an app, delete its file and its images, rebuild and redeploy the API. Existing feedback for it stays in
the database and is still listed in the admin page.

## Feedback board

`feedback.html` with `assets/feedback*.{js,css}`, backed by the Cloudflare Worker in `feedback-api/` (see its
README). `assets/feedback-apps.js` is generated by `build.py`.

## Telling search engines about changes (IndexNow)

After a change is live, `python3 tools/indexnow.py <changed page URLs>` tells Bing and the other IndexNow engines
straight away (`--site HOST` sends a whole site's sitemap). It works for all four sites. Google ignores IndexNow and
reads the sitemaps in Search Console instead.
